# Security and reproducibility review

The deployed interface remains authenticated and exposes approved public SEC data only. Histories accept CIKs, supported metric names, frequencies, dates and approved release identifiers; they do not accept SQL or object keys. Missing authentication, arbitrary SQL, unknown companies, unapproved releases, incorrect expected versions and unsupported newer company cutoffs were tested against the deployed service. Unit tests cover entitlements, bounded requests/responses, signed pagination and malformed contexts. No licensed source was enabled.

Historical release selection resolves only root-pinned previous manifests. Inherited company payloads must match an explicitly permitted source release, registry, CIK and content hash. Query-cache identities include the selected release. Updated company cutoffs are hash-pinned entry metadata, and cross-company terminal comparisons require a common actual availability cutoff. Exact decimal strings and signed source terms remain distinguishable from derived calculations.

Raw SEC candidates, normalized objects, implementation versions and publication roots remain immutable. The full archive SHA is declared source metadata; this run verifies individual members and ranged reads against the pinned archive ETag/header/name/size/CRC/member hash. This is not a new whole-archive SHA certification. Native release metadata and source archives preserve reconstruction even if working Iceberg snapshots are later maintained or expired.

The Basin experiments use existing protected operator credentials and isolated public tables. No broad credential was installed into financial-history serving. The narrow read-only SQL credential gate remains failed because token provisioning is forbidden with current credentials; storage permission behavior has not been established for an unissued candidate. Custom TLS certificate/settings inspection remains blocked by account permissions. Existing production pointers, custom routing and licensed archives were unchanged.

Live rollback activated the prior known-good staging Worker version and reproduced Microsoft observations, then restored the full-universe version and verified identical observations. All three protected CURRENT hashes were rechecked after restoration. This is a staging rollback demonstration, not a production-pointer promotion.
