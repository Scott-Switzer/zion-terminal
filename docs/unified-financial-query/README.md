# Unified financial query foundation

The isolated public SEC multi-table pilot runs through the existing authenticated private dataset service. It preserves exact decimal strings, source nulls, revision availability, source hashes and explicit coverage gaps. It does not certify the whole collection or enable licensed SQL.

Use `GET /private/v1/datasets/financial-query` with the existing private bearer token. Optional fixed inputs include `cik=0001477333`, `as_of=2024-01-01T00:00:00Z`, `limit=100` and `explain=true`. Credentials remain server-side. There is no free-form SQL endpoint. The pilot uses two CIK anchors and one exact SEC revenue concept, retaining six source revisions for three annual contexts; it is deliberately bounded and not a full company financial history.

Read [architecture, security and cost decision](architecture.md), [machine-readable acceptance gates and benchmarks](acceptance-gates.json), and [next implementation sequence](next-plan.md).

Physical object counts include metadata, archives and unrelated code assets within those stores; they are not counts of financial records or queryable tables. Financial and lakehouse catalogs enumerate 14 and 76 registered tables respectively, including isolated pilot tables; research and filings catalog registration remains unverified. No licensed tables were scanned by Basin.

All 805 registered manifest hashes match. Of 41,485 registered object references, 41,484 resolve with matching size and one legacy path reference remains unresolved. The 350 October 5 errors split into 340 release directories containing objects without the expected manifest, and ten valid JSON manifests exceeding the old 1 MiB reader bound (1.3–4.2 MB). This identifies the failure conditions, not the original producer cause or completeness of those releases. Full protected metadata/error details are in the operator evidence directory below.

Independent Python and DuckDB calculations match the public Basin join. Live tests cover authorization, fixed SQL scope, historical availability, exact arithmetic, nulls, caching, EXPLAIN and overflow rejection. Appending one owned synthetic canary creates a new snapshot and the prior policy returns HTTP 409; a new immutable pilot-only policy restores access. Original snapshots and production CURRENT pointers are preserved. Catalog snapshot lists are canonicalized by snapshot ID because their response order varies; no integrity fields are omitted.

Validation includes 149 Python tests, 39 JavaScript tests and 79 existing live route checks, plus 19 new private SQL acceptance checks. The report records 14 PASS and six FAIL gates. Exact live timings, engine scan metrics, evidence hashes and individual PASS/FAIL gates are in the machine report. Measurements are single-run checks, not latency SLOs or a load test. DuckDB validation uses one thread, 64 MB and no external access; it is not a deployed fallback.

Remaining failed gates prevent broader promotion: exhaustive object decodability and registration reconciliation, one legacy reference, narrowly read-only runtime credentials, canonical financial certification and current custom-hostname reachability. Local TLS negotiation to `api-thin-staging.scotttunnel.xyz` failed during final checks; the same authenticated service passes through its existing workers.dev origin. No custom-domain route configuration was changed.

Reproduce from the repository using the audit/build/publish scripts under `scripts/`, followed by `financial_query_acceptance.py --source <public-sec-pilot-input.json> --output <report.json>`. Catalog publication requires PyIceberg/PyArrow; audit and policy registration require Boto3. Provision credentials locally, never in command arguments or logs. The operator-only synthetic version test appends at most one owned test record and leaves old snapshots intact. Re-running it after policy refresh is not a substitute for a new source-version test.
