# Cost evidence and bounds

No account billing receipt was available for this sprint. Actual charged cost is therefore unknown; response time, request counts and storage bytes are operational evidence, not an invoice.

The previous user-approved $5 Cloudflare run ceiling used a conservative reserve containing 8 GB of storage for a full month, a full paid Class A operation unit, a Class B unit and bounded SQL/operations headroom. Its fresh-publication allowance was 200 MB; the prior SEC publication consumed 96.64 MB. The first unactivated research candidate added 7,587,532 immutable bytes. The expanded candidate remains subject to its 12 MiB publication cap, so both research candidates fit inside the previously reserved fresh-storage allowance. This does not authorize another paid operation unit or additional provider spending.

Native market processing reuses existing stored objects and original provider JSON. Targeted official SEC cover documents repair historical identity only after existing resource evaluation; no paid provider acquisition or WRDS collection occurs. Immutable writes use create-only semantics and hash readback; the publication receipts record exact new-object counts and bytes. Reads and small metadata calls are recorded separately.

Matched SEC benchmarks use the identical original 20-company query cohort and parameters before/after deployment. Legacy route object-read counts are uninstrumented and remain null. New research limits report successful source-object GETs, bytes read and request-local cache hits. Response bytes are not substituted for scan bytes, and observed repeat hits are not proof of a controlled globally cold cache.
