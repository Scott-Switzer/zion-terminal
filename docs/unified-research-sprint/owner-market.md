# Private owner Alpaca history

`prepare_owner_market_release.py` reads only the existing, explicitly Alpaca source paths in `financial-system-datasets`. The producer's bucket is authoritative: the WRDS-private bucket is not the location of these normalized objects. The program makes no provider requests, writes no cloud objects and emits only an aggregate receipt. Local output directories are mode 0700 and files 0600. Parent publication must retain owner authentication and the `PRIVATE_OWNER_ALPACA_RESEARCH_ONLY` entitlement; this is not a public redistribution grant.

The bounded cohort is 23 provider symbols, with 22 nonempty histories and one explicit empty result. This is a price-history cohort, independent of SEC financial certification. The native projection verified all 13 input Parquet hashes/byte sizes and their combined 856,633 physical rows, selected 3,971 observations, and found zero conflicting sessions. Sixteen original raw JSON pages were separately SHA-verified and parsed with Decimal; every selected normalized number was checked against its raw source value before original decimal strings were retained. Total input was about 42 MB and local payloads under 5 MiB. No provider price value was returned into model tool outputs.

Most selected history comprises 252 sessions in 2019. BAC, DIS and CSCO cover 2019 Q1; AAPL, MSFT, NVDA and JPM have only the two 2016 canary sessions. UNH has no selected bars. Existing 2020 batches cover other gap-focused symbols, with no overlap with this cohort or the proposed SEC 20-company cohort. Date ranges describe observed source coverage, not continuous listing or session certification. Missing calendar sessions are not inferred without an independently verified trading calendar.

## Numeric and identity contract

Payload schema is `owner-market-history-v1`; the root is `owner-market-release-v1`. Each root `symbols` entry pins the local payload file, SHA-256, byte count, observed count and exact first/last session. Root identity is the hash of the canonical root content before adding `release_id`.

The original Parquet normalizer used FLOAT64. Consequently, converting its numbers to strings alone does not satisfy original-source decimal preservation. This adapter re-reads only the necessary existing raw pages, verifies their source hashes and constructs numeric strings from original JSON decimal tokens. Published native payloads declare `ORIGINAL_RAW_DECIMAL_TOKEN_VERIFIED`. The pure projection helper defaults to `FLOAT64_PROJECTION_UNCERTIFIED` unless the raw reconciliation gate has passed. No FLOAT64-only fallback is promoted by this command.

Every observation retains all deduplicated `source_record_ids`. `source_records[id]` resolves provider symbol, session, feed and original page SHA; `source_pages[sha]` resolves the bucket, key, SHA, retrieval time and request-currency evidence. A source record ID hashes the canonical original source-page reference plus symbol/session/feed/raw/none context. Identical bars merge IDs; conflicting values at one provider-symbol/session produce a `CONFLICTING_SOURCE_BARS` gap, with every conflicting source ID preserved and no arbitrarily selected winner.

Security identity is `alpaca:sip:source-symbol:<SYMBOL>`. Current Alpaca UUID associations are separate, explicitly current-source observations with historical validity UNKNOWN. They never become historical security IDs or ticker-to-CIK joins. Source requests used `asof=-`, preserving provider-symbol labels without Alpaca's historical rename mapping.

The stored schema's original currency remains `source_currency=UNKNOWN`. Derived USD is permitted only after matching the original raw hash/key to a bounded stored request manifest, verifying its official stock-bars endpoint, SIP feed, raw adjustment and `asof=-`, then verifying currency omitted or explicitly USD. The [official historical bars reference](https://docs.alpaca.markets/us/reference/stockbars) documents the USD default. Each observation retains that distinct request evidence; no unsupported currency substitution is performed.

Raw/NONE basis is preserved. Market availability is null, historical knowledge time is NOT_ESTABLISHED, and retrieval time is never substituted. Corporate actions are not integrated because source-specific rights and historical identity were not established. Retrospective owner charts can display these source observations; financial valuation requiring an issuer bridge, split adjustment, historical shares or historical availability must fail its independent gates.

## Bounds and validation

The command caps 20 Parquet references, 8 MiB per object, 40 MiB aggregate normalized inputs, 100 MiB overall native data input, 200 metadata reads, 30 selected symbols, 1 MiB per output and 5 MiB aggregate outputs. It parses Parquet in 10,000-row batches. Six unit tests cover duplicate lineage, conflicts, unknown currency, request-origin rejection, nonfinite/wrong-basis rejection, decimal lexical precision, resolvable provenance and differing proof metadata.

## Unified immutable publication

`publish_unified_research_release.py` publishes only the approved companion artifacts and this already verified owner projection. Before its first mutation, it verifies the current B39 financial root by exact SHA/bytes and PUBLIC_SEC_ONLY policy, then verifies each companion member hash against the current company's hash-pinned catalog entry, registry hash, explicit serving release, actual materialization release and approved source-release allowlist. The companion's historical proof context is separate from its artifact/materialization identity. No unchanged or original financial payload is rewritten.

The `unified-research-release-v1` root pins 20 certification files, the public SEC point-identity fixture, the rewritten market manifest, the exact financial root, the three current implementation files and the separately captured executed certifier. Its content identity includes every source-artifact hash. Market payload bytes remain exact; only the market manifest replaces local filenames with immutable R2 references while preserving the original projection release and local manifest SHA. Policy forbids WRDS paths, unsupported market availability and incomplete source-ID lineage.

Publication is capped at 100 creates and 12 MiB. Every object uses conditional create and exact hash readback; the unified root is written last. Existing conflicting objects fail verification. Neither CURRENT pointers nor Worker configuration are mutated. A protected aggregate receipt records the release/root hash, written bytes, calls and zero provider requests. Deployment remains a separate operation owned by the coordinator.
